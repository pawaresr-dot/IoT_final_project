# ระบบต้นแบบแขนกลนำวัตถุออกจากตารางตามคำสั่งผู้ใช้

สถานะเอกสาร: ร่างจากผลที่มีหลักฐานในโครงการ ณ 29 ตุลาคม 2026
ยังไม่ใช่รายงานยืนยันว่าระบบหยิบวางครบวงจรสำเร็จ

## 1. วัตถุประสงค์

พัฒนาระบบที่ผู้ใช้เลือกช่องบนตาราง 2×2 และสั่งแขนกลนำวัตถุออกไปวางบริเวณที่กำหนด
ใช้ภาพจากกล้องตรวจการมีวัตถุ และแสดงสถานะผ่านเว็บภายในเครื่อง

## 2. อุปกรณ์และโครงสร้าง

- SO-ARM100 follower: แขนทำงาน 5 ข้อต่อและกริปเปอร์
- Raspberry Pi และกล้อง IMX708: ส่งภาพให้เครื่องควบคุม
- Mac และ Python environment `lerobot`: ประมวลผลภาพและสื่อสารกับมอเตอร์
- แขน leader: อุปกรณ์เสริมสำหรับสอนการเคลื่อนไหว แต่ยังไม่ใช้เป็นเส้นทางหลักของเดโม

โครงสร้าง: ผู้ใช้ → เว็บควบคุม → ตรวจคำสั่ง/ตำแหน่ง → มอเตอร์ follower
กล้อง → ตรวจตาราง/การเปลี่ยนแปลงภาพ → แสดงสถานะ
การนำสองสายงานมาใช้สั่งหยิบวัตถุจริงยังต้องทดสอบรวม

## 3. วิธีการ

### การมองเห็น

กำหนดมุมตาราง แปลงภาพให้แบ่งเป็นสี่ช่อง และเปรียบเทียบกับภาพตารางว่าง
ผลที่ได้เป็นการตรวจความเปลี่ยนแปลง/การครอบครองช่อง ไม่ใช่โมเดลเรียนรู้ที่ฝึกแล้ว
เมื่อกล้องหรือตารางย้าย ต้องตั้งกรอบและภาพอ้างอิงใหม่

### การควบคุมแขน

ใช้ calibration ที่บันทึกไว้แปลงพิกัดมอเตอร์ เก็บท่าลอยเหนือช่อง ท่าจับ ท่ายก และท่าวาง
เคลื่อนระหว่างท่าด้วยเป้าหมายทีละน้อย และชดเชยความคลาดเคลื่อนแบบจำกัดที่ไหล่และศอก
วิธีนี้เป็นการเล่นเส้นทางตามท่าที่สอน ไม่ใช่ AI สร้างเส้นทางใหม่อิสระ

## 4. ผลที่มีหลักฐานแล้ว

| รายการ | ผลและขอบเขต |
|---|---|
| อ่านมอเตอร์ follower | อ่านตำแหน่งได้ครบ 6 ตัว |
| ภาพจาก Pi | ตรวจล่าสุดมีภาพสด |
| การตรวจวัตถุบนตาราง | มีบันทึกทดสอบวันที่ 22 ต.ค.; ต้องตั้งภาพอ้างอิงใหม่หากฉากเปลี่ยน |
| เส้นทางแขนเปล่า | เส้นทางย้ายระดับสูงและเส้นทางกลับจากจุดจับผ่านแยกการทดลอง วันที่ 22 ต.ค. |
| กริปเปอร์ follower | หลังเปลี่ยนตัวควบคุม เปิดจาก2049 ไป2127 ใกล้เป้า2129 ผ่านหนึ่งครั้ง ขณะพยุงแขน; ยังไม่ยืนยันการปิดคีบหรือรับน้ำหนัก |
| แขนสอน | เปิดบริการอ่าน leader และโหมดตาม 5 แกนผ่าน HTTP ของตัวควบคุม follower แล้ว ยังพบ voltage error เป็นช่วง ๆ ที่กริปเปอร์ leader ซึ่งไม่ใช้เป็น input; ปัญหาฮาร์ดแวร์ตัวนี้ยังไม่ถูกแก้ |
| ลองเข้าจับวัตถุแบบระยะสั้น | ขยับเข้า ปิดกริปเปอร์ และขยับกลับได้ แต่ภาพยังไม่ยืนยันว่าวัตถุยก จึงไม่นับว่าหยิบสำเร็จ |
| หยิบวัตถุจริงครบวงจร | ยังไม่มีผลผ่าน |
| หน้าเตรียมเดโม | เลือกช่อง แสดงแผน 13 ขั้น และตรวจมอเตอร์แบบอ่านอย่างเดียวได้ ยังไม่สั่งหยิบจากหน้านี้ |
| ควบคุมระยะสั้น | โหลดโปรแกรมใหม่แล้ว เปิดกริปเปอร์และขยับ shoulder_lift +11 ticks ผ่านบนแขนจริง; ไม่ใช่การหยิบครบวงจร |
| สอนด้วยมือ | รอบใหม่735เฟรม/85.235วินาทีบันทึกสมบูรณ์ กลับจุดเริ่มด้วยแขนจริงผ่าน; การหยิบยังไม่ยืนยัน |
| ทดสอบก้ามที่เพดานแรง60% | เปิด–กลับ80ticksผ่าน เป้าหมาย2206/2126 อ่านจริง2197/2137 อุณหภูมิสูงสุด43°C คืนค่า50%และปิดแรงแล้ว ไม่ใช่ผลการวัดแรงคีบหรือหยิบสำเร็จ |
| เล่นเส้นทางและปล่อยนอกตาราง | เล่น259จุดครบโดยมีพัก/รับช่วงที่จุด25และใช้ศอกP24ชั่วคราว ภาพสดเห็นวัตถุไปด้านขวานอกตาราง เปิดก้ามเป้า2373/จริง2366แล้ว ยังไม่ยืนยันว่าพ้นพื้นตลอดทาง จึงไม่เรียกว่าหยิบยกครบวงจรสำเร็จ |
| ผู้ใช้สังเกตจากด้านข้าง | ผู้ใช้ยืนยันว่าเห็นวัตถุพ้นพื้น เป็นรายงานจากผู้ใช้ ไม่ใช่การตรวจความสูงอัตโนมัติ และไม่ได้ระบุหมายเลขรอบ |
| ปุ่มเดียวรวมลำดับ | เพิ่มกลับจุดเริ่ม/เล่นเส้นทาง/เปิดก้ามแล้ว แต่รอบฮาร์ดแวร์ล่าสุดหยุด37/259จากค่าอุณหภูมิไหล่150°Cผิดปกติหลังค่าประมาณ41°C สาเหตุยังไม่ยืนยัน จึงไม่นับรอบนี้สำเร็จ |
| ชุดทดสอบซอฟต์แวร์ | รันล่าสุด 74 tests ผ่าน; เป็นการทดสอบตรรกะและมอเตอร์จำลอง ไม่ใช่ 74 การทดลองฮาร์ดแวร์ |

หลักฐานเส้นทางเดิมอยู่ใน `vision_state/transfer_dryrun_pass_20261022.md`
และ `vision_state/source_return_pass_20261022.md` การผ่านครั้งนั้นไม่รับรองฉากหรือฐานแขนที่เปลี่ยนแล้ว

## 5. ข้อจำกัดและปัญหา

ตามคำขอผู้ใช้ปิดเฉพาะตัวตัดอุณหภูมิเสริมในโปรแกรม โดยยังอ่านค่าดิบและตรวจ servo alarm
อ่านยืนยันทั้ง6ตัวว่าการป้องกันความร้อนในservoยังเปิดและมีเกณฑ์70°C ไม่เปลี่ยน EEPROM
หลังเปลี่ยนโหมดนี้ยังไม่มีผลทดสอบการเคลื่อนไหวใหม่ จึงไม่ใช้ยืนยันว่าปัญหาทั้งหมดแก้แล้ว

ยังต้องยืนยันการคีบ การรับน้ำหนัก และความแม่นยำกับวัตถุจริง
การทดลองกริปเปอร์รอบที่เพิ่มบันทึกค่าขณะเกิดเหตุอ่าน Status=0, 58°C, 11.9V
จึงหยุดตามเกณฑ์อุณหภูมิ ต่อมาอ่านหลังหยุดได้ 38°C, Status=0, 12.0V
ยังไม่ยืนยันว่าเป็นความร้อนจริงหรือค่าอ่านผิดปกติ และไม่สรุปว่าเซอร์โวเสียหรือไฟตกถาวร
เกณฑ์หยุดเมื่อแรงดันลดจากค่าเริ่ม 0.6V ถูกนำออกจาก bridge และ source ตัวควบคุม follower แล้ว
ตัวควบคุม follower หยุดรุ่นเก่าตรวจปิดแรงแล้ว และโหลดรุ่นใหม่เรียบร้อย
ยังคงตรวจขอบเขตแรงดันและข้อผิดพลาดมอเตอร์

รายละเอียดผลควบคุมระยะสั้นกับฮาร์ดแวร์อยู่ใน `vision_state/manual_control_pass_20261028.md`
ผลลองเข้าจับระยะสั้นอยู่ใน `vision_state/grasp_attempt_20261028_01.md`
รอบนี้ไม่ใช่การทดลองครบวงจร จึงไม่รวมในตารางอัตราสำเร็จครบวงจรด้านล่าง

## 7. สรุปเบื้องต้น

โครงการมีระบบภาพสด การตรวจตาราง การอ่านมอเตอร์ และตัวควบคุมเส้นทางแขนเปล่าแล้ว
ส่วนที่ยังไม่ยืนยันคือการหยิบวัตถุและการรวมระบบตามคำสั่งผู้ใช้ครบวงจร
แผนก่อนส่งคือทำหนึ่งช่องให้ครบก่อน แล้วขยายเท่าที่มีผลทดสอบจริงรองรับ
