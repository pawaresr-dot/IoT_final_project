## วิธีระบุมุมตาราง

โปรแกรมจะลองอ่าน ArUco marker ก่อน และถ้าไม่พบ จะหาขอบกระดาษลังสีอ่อนบนพื้นหลังสีเข้มโดยอัตโนมัติ จากภาพที่ส่งมา วิธีหลังก็หาขอบและเส้นแบ่งที่วาดไว้ได้แล้ว จึง **ยังไม่จำเป็นต้องติด marker** ถ้าภาพจาก Pi Camera มีแสงและมุมใกล้เคียงกัน

หากการหาขอบจากกล้องจริงไม่เสถียร สามารถพิมพ์ภาพในโฟลเดอร์ `markers/` (`DICT_4X4_50` หมายเลข 0–3) ให้แต่ละอันกว้างประมาณ 4–5 ซม. แล้วติด **นอก** ตาราง โดยให้มุมของลาย marker ที่ใกล้ตารางแตะมุมตารางตามนี้:

```text
marker 0: มุมซ้ายบน     marker 1: มุมขวาบน
marker 3: มุมซ้ายล่าง  marker 2: มุมขวาล่าง
```

โปรแกรมใช้มุมด้านในของ marker ทั้งสี่สร้างภาพมองจากด้านบน จึงยังหาแนวช่องได้แม้กล้องมองเฉียงเล็กน้อย ถ้าทั้งการหาขอบกระดาษลังและ marker ใช้ไม่ได้ ให้ทำไฟล์ JSON ที่มีพิกัดมุมตารางจากภาพจริงเรียง `[ซ้ายบน, ขวาบน, ขวาล่าง, ซ้ายล่าง]` เช่น:

```json
[[120, 90], [720, 100], [700, 630], [130, 620]]
```

พิกัดตัวอย่างนี้ต้องเปลี่ยนตามภาพจริง และวิธีนี้ใช้ได้เมื่อกล้องกับขนาดภาพไม่เปลี่ยน

### ตรวจจากไฟล์ภาพ

ในเครื่องนี้มี Python environment ชื่อ `lerobot` ซึ่งมี OpenCV อยู่แล้ว:

```sh
cd /Users/pawacha/Documents/programming/year2/IoT/final_project
/Users/pawacha/miniforge3/envs/lerobot/bin/python grid_vision.py \
  --reference empty.jpg --image current.jpg --preview preview.png
```

ถ้าใช้พิกัดมุมเอง ให้เพิ่ม `--corners corners.json` ผลลัพธ์เป็น JSON ของทั้งสี่ช่องและไฟล์ภาพ `preview.png` สีแดงหมายถึงพบความเปลี่ยนแปลงมากพอที่จะนับว่ามีวัตถุ สีเขียวหมายถึงว่าง โปรแกรมพยายามอ่านเส้นแบ่งจากภาพตารางว่างก่อน หากหาไม่เจอจึงแบ่งกึ่งกลาง ค่า `changed_fraction` ใช้ปรับความไวด้วย `--occupied-fraction` (ค่าเริ่มต้น `0.04`) และ `--pixel-threshold` (ค่าเริ่มต้น `35`)

เมื่อต้องการตรวจคำสั่งย้ายของ ให้เพิ่ม `--from-cell top_left --to-cell bottom_right` โปรแกรมจะยอมรับเมื่อช่องต้นทางมีของและปลายทางว่างเท่านั้น พร้อมคืนค่า `move` ใน JSON ขั้นนี้ยังไม่สั่งแขนกล

ถ้ารันบน Raspberry Pi OS ที่ต่อ Camera Module ให้ถ่ายภาพดังนี้:

```sh
python3 capture_board.py --backend pi --output empty.jpg
# วางของบนตาราง แล้วถ่ายอีกภาพ
python3 capture_board.py --backend pi --output current.jpg
python3 grid_vision.py --reference empty.jpg --image current.jpg --preview preview.png
```

สำหรับกล้อง USB เปลี่ยนเป็น `--backend usb --device 0` ต้องใช้มุมกล้อง แสง และความละเอียดภาพเดิมเสมอ บน Raspberry Pi OS ถ้ายังไม่มี ให้ติดตั้ง `python3-picamera2` สำหรับ Camera Module และ `python3-opencv` สำหรับการตรวจภาพผ่านแพ็กเกจระบบ

`hold_arm_pose.py` โหมด `/manual` ที่พอร์ต 8766 ให้ตัวหลังเป็นผู้ใช้ USB follower
เพียงตัวเดียว ฝั่งแขนสอนเปิดเฉพาะ USB leader และส่ง bounded jog ผ่าน HTTP
แทนการเปิด USB follower ซ้ำ ไม่ต้องปิดแรงพยุงเพื่อเชื่อมแขนสอน

- เริ่มโปรแกรมแบบหยุดตาม กดเริ่มเพื่อจับจุดอ้างอิงใหม่ ไม่ปรับท่าเริ่มให้เหมือนกันทันที
- รับข้อมูลควบคุมเฉพาะ 5 แกน ทุกแกนต้องปิดแรง ไม่มี Status alarm และผ่านการตรวจไฟ/อุณหภูมิ
- กริปเปอร์ leader ไม่ใช่ข้อมูลควบคุม ข้อผิดพลาดของตัวนี้แสดงเป็น warning แยก
  ไม่ล้าง alarm หรือเปลี่ยนค่าป้องกัน ไม่สั่งแรงไปยัง leader
- ถ้าข้อมูล 5 แกนที่ใช้งานขัดข้อง จะหยุดส่งคำสั่งโดยไม่ปิดแรง follower
  การป้องกันและการตรวจฮาร์ดแวร์ของ follower ยังทำโดย worker เดิม
- ปุ่มกริปเปอร์ในหน้าสอนใช้ควบคุม follower โดยตรงผ่าน worker เดิม
- ปุ่มบันทึก grasp/lift/place หยุดตามและเก็บ encoder แขนจริง เมื่อถึงเป้าหมายแล้ว
  ลงไฟล์ `leader_teaching_<เวลา>_<session>.json` ไม่เขียนทับข้อมูลท่าเดิม
- ข้อมูลท่าสอนยังเป็น observation ไม่ใช่ผลรับรองหยิบสำเร็จหรือเส้นทาง replay ที่ผ่านทดสอบ
- ช่วงทดลอง input จำกัดประมาณ 180 ticks (~16°) จากจุดจับอ้างอิง และยังอยู่ภายใต้
  ขอบเขต session/ข้อต่อของตัวควบคุม follower ไม่ปรับเพิ่มช่วงโดยอัตโนมัติ

ส่วนด้านล่างเป็น **bridge รุ่นเดิมแบบเปิดสอง USB** ห้ามรันพร้อมกับตัวควบคุม
follower ที่เปิดแรงอยู่ และไม่ใช่บริการที่กำลังใช้ล่าสุด:

รัน `leader_follower_bridge.py` ด้วย environment `lerobot` แล้วเปิด
`http://127.0.0.1:8767/` โปรแกรมเริ่มแบบอ่านค่าทั้งสองแขนเท่านั้น ไม่เปิดแรง
และใช้ USB เพียงโปรแกรมเดียว อย่ารัน `hold_arm_pose.py`, teleoperate หรือ
โปรแกรมอ่านมอเตอร์อื่นพร้อมกัน

- Leader: `/dev/cu.usbmodem5B421342561` — ไม่มีคำสั่งเขียนมอเตอร์ไปยังแขนสอน
- Follower: `/dev/cu.usbmodem5B421348831` — ใช้ calibration เดิม
- ปุ่มเริ่มตามจะจับตำแหน่งปัจจุบันเป็นจุดอ้างอิงแบบ relative จึงไม่กระโดดตาม
  ท่าของ leader ที่ต่างกันตอนเริ่ม ใช้เพื่อทดลองตาม 5 ข้อต่อเท่านั้น
- กริปเปอร์อ่านค่าได้ แต่ยังไม่เปิดแรงหรือควบคุมตาม
- ถ้าข้อต่อ follower ชิด/เลยช่วงที่บันทึกไว้ ต้องรองรับและจัดท่าออกจากปลายช่วง
  ขณะปิดแรงก่อนกดเริ่ม ไม่ต้องบันทึกท่าหรือ calibration ใหม่โดยอัตโนมัติ
- ปุ่มค้างท่ายังคงแรงพยุงไว้ กดเริ่มอีกครั้งเพื่อจับจุดอ้างอิงใหม่ได้
- ก่อนปิดแรงต้องรองแขน เมื่อมอเตอร์/การสื่อสารผิดปกติ โปรแกรมอาจปิดแรงและแขนอาจร่วง

โหมดนี้ยังไม่ได้บันทึก demonstration หรือฝึกโมเดล และไม่ใช่การตามตำแหน่ง absolute
ที่ยืนยันความตรงของท่าทั้งสองแขนแล้ว ต้องทดสอบตามทีละข้อต่อแบบช้า ๆ ก่อน

### ทดสอบแรงพยุงแขน

เพิ่มโหมด `/manual` สำหรับควบคุมจากท่าปัจจุบัน และ `/jog` สำหรับขยับสั้น ๆ
ใน worker เดียวกับการพยุงแขน: ปุ่มข้อต่อ ±11 ticks (ประมาณ 1°), กริปเปอร์ ±80 ticks
ข้อต่อจำกัดสะสมจากท่าเริ่ม session 180 ticks และยังตรวจขอบเขต/สถานะ/อุณหภูมิ
ไม่มีการเปลี่ยน P/I/D หรือ EEPROM ในโหมดนี้ กริปเปอร์ไม่เปิดแรงจนกว่าจะส่งคำสั่งกริปเปอร์
เป้าหมายเริ่มต้นตั้งที่ encoder ก่อนเปิดแรง และเมื่อหยุดจะตรวจปิดแรงทุกมอเตอร์ที่เปิด
เอาเกณฑ์แรงดันลดจากค่าเริ่ม 0.6V ออกจากตัวควบคุมนี้ด้วยแล้ว ตามคำขอเดิม
ยังคงใช้ขอบเขตแรงดันที่ตั้งใน servo และการแจ้งข้อผิดพลาดของ servo

การอัปเดตไฟล์ไม่เปลี่ยนโปรแกรมที่กำลังรัน ต้องรองแขนก่อนหยุดตัวเดิมและโหลดใหม่
ชุดท่าทดลองใหม่บันทึกแยกใน `pick_place_poses_20261028_session1.json`
ขณะบันทึกมีเพียงท่า approach ที่ operator จัดให้ ยังไม่รับรองระยะจับและไม่ใช่ calibration ใหม่

เมื่อ torque ปิด แขนจะไม่พยุงน้ำหนักตัวเอง ต้องมีมือหรือที่รองรับระหว่างสอนท่า
โปรแกรม `hold_arm_pose.py` ตรวจ calibration และสถานะมอเตอร์ ตั้งเป้าหมายตรงตำแหน่ง
จริงก่อนเปิดแรงเฉพาะ 5 แกนแขน โดยไม่เปิดแรงกริปเปอร์และไม่เรียกท่าที่บันทึกไว้
โปรแกรมเริ่มแบบ idle ไม่เปิดแรงเมื่อรัน เปิดแรงได้จากปุ่มในหน้าเว็บหลังตรวจท่า:

```sh
/Users/pawacha/miniforge3/envs/lerobot/bin/python hold_arm_pose.py
```

ดูสถานะและปุ่มหยุดที่ `http://127.0.0.1:8766/` ขณะเปิดแรงไม่ควรฝืนจัดแขนด้วยมือ
ก่อนกดปุ่มปิดแรง ต้องประคองหรือรองรับแขนและวางวัตถุให้เรียบร้อย เมื่อเกิด fault
โปรแกรมจะพยายามปิดแรงทุกแกนและตรวจยืนยัน จึงต้องมีที่รองรับระหว่างทดสอบด้วย
หลัง fault โปรแกรมไม่เปิดแรงซ้ำเอง

ตัวควบคุมใช้พอร์ต USB ของแขนแต่เพียงโปรแกรมเดียว อย่ารันโปรแกรมอ่าน/บันทึกท่าอื่น
พร้อมกัน ให้รองรับแขน ปิดแรง แล้วจึงบันทึกท่าหรือเริ่มโปรแกรมใหม่
โปรแกรมตรวจซ้ำค่าแรงดันผิดปกติทันทีและเก็บค่าที่อ่านทั้งสองครั้ง โดยไม่แก้เกณฑ์ป้องกัน
ของ servo ค่าเปิดและระยะคีบที่สอนวันนี้อยู่ใน `pick_place_poses.json` แยกจากท่าเดิม

### ลำดับการเตรียมหยิบวาง

1. ถ่ายภาพตารางจริงทั้งตอนว่างและตอนมีวัตถุ เพื่อปรับการตรวจจับให้ตรงกับวัสดุและแสงจริง
2. ตรวจว่าแขนทุกแกนสื่อสารและขยับได้ รวมทั้งมี calibration ของ LeRobot สำหรับ robot ID `pawacha_so100_follower`
3. บันทึกท่าของแขนสำหรับแต่ละช่อง: ท่าลอยเหนือช่อง ท่าจับ และท่ายก รวมถึงท่าเปิด/ปิด gripper และท่าพัก
4. รับคำสั่งต้นทาง/ปลายทาง ตรวจจากกล้องว่าต้นทางมีวัตถุและปลายทางว่าง แล้วทำลำดับ ยก → ย้าย → วาง → ตรวจภาพอีกครั้ง
5. เพิ่มส่วน IoT เช่นหน้าเว็บหรือ MQTT ตามเกณฑ์งานที่อาจารย์กำหนด

สำหรับตัวหมากรุกในขั้นถัดไป อาจต้องถ่ายภาพที่ความละเอียดสูงขึ้น ปรับค่า `--occupied-fraction` ตามขนาดฐานหมาก และสอนท่าจับใหม่ โดยเก็บภาพตารางว่างและภาพที่มีตัวหมากในสภาพแสงจริงเพื่อวัดค่าที่เหมาะสม

กล้องบอกตำแหน่งช่องในภาพได้ แต่ตำแหน่งภาพยังไม่ใช่มุมมอเตอร์ของแขน สำหรับตารางสี่ช่องที่อยู่กับที่ การสอนท่าแขนแยกแต่ละช่องเป็นวิธีเริ่มต้นที่ง่ายและตรวจสอบได้
